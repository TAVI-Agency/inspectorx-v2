## 2026-07-16 — языковая схема lex.uz (разведка живьём, фаза 1 UZ-first)

Факт: у каждой языковой версии акта СВОЙ doc_id. Таможенный кодекс: RU 2876352,
UZ-кириллица 2876354 (1600 «модда», 0 «Статья»), UZ-латиница -2876354 (1600 «modda»).
Префикс /ru/|/uz/ в URL меняет только язык интерфейса. Знак doc_id семантики языка
НЕ несёт (ЗРУ-819: RU-версия = -6445145). Единственный надёжный способ найти
UZ-версию — ссылки в шапке страницы (docContentHeader__item-link, title=«Ўзбекча»/
«O'zbekcha»). Следствия: (1) отдельный кэш по языку из спеки НЕ нужен — кэш и так
по doc_id; (2) гейту нужен парсер шапки language_versions(); (3) выбор графики
(кир/лат) — по графике самой цитаты legal_quote_uz.

### UZ-вход: диагноз и добивка оригиналов (28.07)

**Метрика, мотивировавшая работу.** Объявленная 16.07 метрика фазы 3 (доля
act_paragraphs с verbatim_uz) через 10 дней после мержа фазы 1 показала **0 из 200**.

**Диагноз: шов UZ-first исправен, но ни разу не исполнялся.** verbatim_uz пишется
только при `gate.verified_lang="uz"`, а гейт ставит uz только при наличии
`legal_quote_uz`. УЗ-цитату несут 3 из 267 import_items (все три загружены 13.07,
до фазы 1), в 28 из 28 DR-отчётов `research/incoming` поля `legal_quote_uz` нет вовсе —
весь входной поток русский. Живая проверка гейта на Таможенном кодексе с узбекской
цитатой: ok=True, verified_lang=uz, conf=1.0. То есть чинить нужно вход (заказ
отчётов), а не конвейер.

**Решение: добивка задним числом, без модели в цепочке.**
`research-loop/backfill_verbatim_uz.py` находит узбекскую версию акта по шапке страницы
lex.uz и кладёт дословный текст пункта в пустое verbatim_uz; запись только с `--apply`.
Это не «мимо гейта»: гейт проверяет утверждение модели против первоисточника, а здесь
модели нет — текст берётся с официальной страницы по уже сохранённому номеру пункта.
Прогон `--apply` по проду: verbatim_uz 0 → **75 из 200**, 7 не найдены (приложения и
диапазоны), 118 пропущены честно как легаси-ref из переноса v1. Подробности — LOOP-LOG,
секция «Работа 28.07».

**Решение: колонку `uz_backfill_needed` в БД не заводить.** Список «кого добивать»
точнее выводится из данных (`verbatim_uz is null`), миграция ради дублирующего признака
не окупается. Вместо неё — видимый счётчик прогона `RunSummary.uz_backfill`
(`importer/pipeline.py`, печать в `importer/cli.py`): гейт считал uz_backfill_needed
с фазы 1, но ни один потребитель его не читал — карточки публиковались без узбекского
оригинала молча. Тесты 123 → 131.
