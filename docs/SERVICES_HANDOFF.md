Реализуй модуль УСЛУГ в InspectorX v2 от начала до конца, чтобы в проде появилась готовая первая услуга.

**Сначала прочитай** `docs/SERVICES_PASSPORT_PROPOSAL.md` — это утверждённое фаундером предложение со всей архитектурой, контентом аптеки и списком непроверенных фактов. Работай строго по нему.

**Утверждённые решения фаундера:**
1. Первая услуга — розничная аптека; вторая (если успеешь в этой сессии) — кафе/общепит; грузоперевозки НЕ делать.
2. Ось поиска услуг — ОКЭД (главный код), ИКПУ — второй код в шапке.
3. Оси паспорта услуги: режим допуска (лицензия/разрешение/уведомление/свободно) × 6 этапов жизни бизнеса (старт и допуск → помещение и запуск → текущая работа → проверки → изменения и продление → прекращение). Третьей оси нет. На карточках — пометка «разовое/постоянное».

**Порядок работы:**

1. **Миграция БД** (новая миграция в supabase/migrations, строго аддитивная — товары и RLS не трогать):
   - `services`: добавить `oked_code text`, `admission_mode` (новый enum: license/permit/notification/free), `authority_id` (FK на authorities), `complexity_index int`;
   - `lifecycle_stages`: 6 новых строк для сервисных этапов (коды вида `svc-01-start` … `svc-06-closure`, sort_order после товарных);
   - enum `operation_domain` += `service`; enum `party_role` += `service_provider`; enum `applicability_scope` += `oked_code`, `oked_prefix` (в constraint applicability_code_presence учесть новые значения);
   - `requirements`: добавить nullable `nature` (enum: one_time/recurring) — пометка «разовое/постоянное».
   - Проверить локально (`supabase db start && supabase db reset --local`), потом накат на прод.

2. **Сид контента** (по образцу scripts/generate_v1_content_migration.mjs или отдельной миграцией):
   - услуга «Розничная аптека» (ОКЭД 47.73, admission_mode=license, орган — Агентство по развитию фармотрасли) + алиасы поиска (аптека, dorixona, pharmacy…);
   - ~30 карточек аптеки по этапам из раздела 6 предложения (заголовок-глагол, деонтика, адресат service_provider, орган, санкция, шаги со сроками/стоимостью, документы) + ~15 горизонтальных карточек (scope=all_services) из того же раздела;
   - непроверенные пункты из раздела 7 предложения — НЕ публиковать (status=draft) либо публиковать только то, что верифицировано, с trust_label=ai_draft; ничего не досочинять;
   - суммы храним в БРВ, как в тексте карточек товаров.

3. **Фронтенд (кокпит C, корневые маршруты)**:
   - поиск: переключатель «Услуга» ведёт на страницу услуги `/service/:id` (сейчас ведёт в никуда);
   - страница услуги — зеркало страницы товара: шапка-паспорт (название, ОКЭД+ИКПУ, бейдж режима допуска, лицензиар, сложность), сводка метрик, нить-маршрут с 6 этапами вместо операций (транспорт-ветки нет), список карточек с раскрытием 0→1→2, пейволл как у товаров;
   - кросс-ссылки: на паспорте аптеки — блок «Требования к товару: лекарства», на товарах-лекарствах — «Открываете аптеку?»;
   - пустые этапы не показывать; частично наполненные — пометка «раздел в работе».
