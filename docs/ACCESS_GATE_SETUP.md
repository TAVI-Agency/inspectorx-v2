# Настройка «вход только по одобренной заявке»

Что это даёт: человек оставляет заявку на сайте (/register или /pricing) →
вам приходит сообщение в Telegram с кнопками «✅ Одобрить» / «❌ Отклонить» →
нажали «Одобрить» — человеку автоматически уходит письмо-приглашение, по
которому он задаёт пароль и попадает в приложение с открытым доступом.
Самостоятельно зарегистрироваться нельзя — только через заявку.

Ниже — что нужно сделать руками один раз. Код и миграция уже готовы.

## а) Выключить самостоятельную регистрацию

1. Откройте Supabase Dashboard → ваш проект InspectorX → **Authentication**
   → **Sign In / Providers** (или **Settings** в старом интерфейсе).
2. Найдите переключатель **«Allow new users to sign up»** (иногда называется
   «Enable Signups») и выключите его.
3. Сохраните.

После этого `supabase.auth.signUp()` (обычная регистрация) перестанет
работать даже при прямом обращении — попасть в приложение можно только
через письмо-приглашение, а его отправляет только ваш апрув в Telegram.

## б) Переменные окружения в Vercel

Откройте Vercel → проект InspectorX → **Settings** → **Environment
Variables**. Сначала проверьте, что уже стоят (они нужны были ещё для
календаря дедлайнов):

- `SUPABASE_URL` — адрес вашего проекта Supabase.
- `SUPABASE_SERVICE_ROLE_KEY` — сервисный ключ (Settings → API → service_role в
  Supabase). Если этих двух ещё нет — добавьте, без них вебхук не заработает.

Добавьте три новые:

| Переменная | Что это | Откуда взять |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота, которым он шлёт и получает сообщения | Тот же токен, что уже лежит в Supabase Vault как секрет `telegram_bot_token` (заводили для уведомлений о заявках, 27.07.2026). Если под рукой нет — @BotFather → ваш бот → API Token |
| `TELEGRAM_ADMIN_CHAT_ID` | Чат, из которого принимаются нажатия кнопок | Тот же chat_id, что в Supabase Vault как секрет `telegram_chat_id` |
| `TELEGRAM_WEBHOOK_SECRET` | Произвольная случайная строка — защита от поддельных запросов на вебхук | Придумайте сами: любая длинная случайная строка, например через `openssl rand -hex 32` в терминале, или сгенерируйте в любом генераторе паролей |

Значения `telegram_bot_token` / `telegram_chat_id` в Supabase Vault посмотреть
напрямую нельзя (они зашифрованы), но если уведомления о заявках уже
приходят вам в Telegram — значит бот и чат те же, токен можно взять заново у
@BotFather (это не сбросит вебхук — старый токен просто перестанет быть
действительным, если вы его перевыпустите; лучше не перевыпускать, а
использовать существующий).

После добавления переменных — **Redeploy** (Vercel → Deployments → … →
Redeploy), иначе функция их не увидит.

## в) Подключить вебхук в Telegram

Одна команда в терминале (замените `<TELEGRAM_BOT_TOKEN>` и
`<TELEGRAM_WEBHOOK_SECRET>` на значения из шага б):

```bash
curl -s -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://inspectorx.uz/api/telegram/webhook", "secret_token": "<TELEGRAM_WEBHOOK_SECRET>"}'
```

Ответ должен быть `{"ok":true,"result":true,...}`. Проверить, что вебхук
встал, можно так:

```bash
curl -s "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo"
```

В ответе поле `"url"` должно быть `https://inspectorx.uz/api/telegram/webhook`,
а `"last_error_message"` — отсутствовать или быть старым (до настройки).

## г) Проверка «от и до»

1. Откройте /register на сайте, заполните тестовую заявку своим email
   (лучше тем, к которому есть доступ).
2. В Telegram должно прийти сообщение с именем/контактом/email и двумя
   кнопками.
3. Нажмите «✅ Одобрить». Сообщение должно измениться — снизу добавится
   строка «✅ Одобрено», кнопки исчезнут.
4. На указанный email должно прийти письмо-приглашение от Supabase.
   Перейдите по ссылке — откроется страница, где нужно задать пароль.
5. После задания пароля должно открыться приложение (раздел «Мои товары»).
6. Повторное нажатие на ту же кнопку (если случайно нажали дважды) должно
   просто показать всплывающее «Уже обработано» — ничего не сломается и
   повторное письмо не уйдёт.

Если на шаге 2 сообщение не приходит — уведомления о заявках вообще не
настроены (см. `20260727120000_lead_notifications.sql`, секреты Vault). Если
кнопки не реагируют — проверьте шаги б/в ещё раз (чаще всего забывают
Redeploy после добавления переменных).
