## Схема БД (всплыло при проектировании 11.07.2026)

- **Дерево ТН ВЭД как полноценные category-строки в `products`** — колонка `parent_id`
  уже заложена; наполнить промежуточные уровни (2/4/6/8 знаков), когда делаем
  браузинг каталога (§3b п.2в TARGET_FORMAT). Пока — только `hierarchy_path` (breadcrumb).
- **`jurisbase_paragraph_id` в `act_paragraphs`** (имя поля историческое, переименование —
  отдельной миграцией, ADR-0002) — добавить колонку, когда LegalX начнёт отдавать
  стабильные ID пунктов (запланировано на неделю 2–3).
- **Rationale применимости** («почему это требование привязано к вашему коду»,
  паттерн Avalara) — [ГИПОТЕЗА] из TARGET_FORMAT §4 ур.2; поле на
  `requirement_applicability`, когда проверим ценность.
- **Отдельные таблицы для шагов/документов** вместо jsonb в `requirement_details` —
  когда появится структурный редактор в админке (сейчас ревьюер правит карточку целиком).
- **Роли в БД (admin / reviewer / content-operator)** — сейчас всё админское через
  service_role; таблица ролей понадобится, когда ревьюеров станет больше одного
  и нужен будет гранулярный аудит в админке.
- **Storage-бакет для файлов ответов** (`user_questions.response_file_url`,
  GR-документы) — настроить при постройке кабинета/GR-потока.
- **Партиционирование / архивация `user_notifications`** — только если объём станет
  проблемой (не раньше тысяч пользователей).
