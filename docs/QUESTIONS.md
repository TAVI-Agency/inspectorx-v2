## Данные / схема

1. **У `products` нет колонки ИКПУ** (только `hs_code`), хотя TARGET_FORMAT §3 требует
   в шапке-паспорте оба кода (ТН ВЭД **и** ИКПУ).
   *Обход:* для реальных товаров показываю только ТН ВЭД; для мок-товаров показываю мок-ИКПУ,
   чтобы демонстрировать целевой вид. Нужна колонка `ikpu_code` (или таблица соответствий).

2. **`sanction_summary` пуст у всех 203 перенесённых требований** — контракт уровня 0
   («санкция одной строкой — обязательна») нарушен контентом, не схемой.
   *Обход:* пустая санкция в строке не рендерится (правило «пустое не показываем»),
   вместо неё ничего. Надо заполнить в контенте (конвейер/админка).

3. **`authority_id` не заполнен у большинства требований** («ведомство» — обязательный
   атрибут уровня 0 по §4).
   *Обход:* сегмент ведомства скрывается, если null. Заполнить контентом.

4. **Акты из v1 грязные**: `title` вида «1. ПКМ-290, ТР\n2. ПКМ-43 (пункт 66*1)» и
   «Источник не указан (перенос из v1)», `number`/`act_type`/`adopted_date` = null.
   *Обход:* показываю title как есть (первой строкой), реквизитная таблица выводит
   только заполненные поля. Нормализовать акты при чистке контента.

5. **Имена товаров — сырые строки классификатора** («2404 11 000 1 | содержащая…»).
   *Обход:* человекочитаемое имя беру из default-алиаса `search_aliases` (IQOS, Молоко),
   официальное название кода показываю рядом (это и требует §3b п.2 — для самопроверки кода).
   ОК ли такое правило именования?

6. **`requirement_contents.title` — не глаголы** («Информация о сертификации» вместо
   «Указать информацию о сертификации») — контракт «заголовок-глагол» нарушен контентом.
   *Обход:* показываю как есть. Править в контенте.
