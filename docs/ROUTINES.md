# ROUTINES — рутины Claude Code (обсуждение 29–30.07.2026)

> **Статус: ОТЛОЖЕНО.** Рутину не ставим, пока не определён «идеальный формат»
> процесса. Этот документ — чтобы обсуждение не пропало: здесь готовая заготовка
> рутины, все ограничения и чек-лист «когда возвращаться».
>
> Уточнение (ADR-0002): «отложено» касается только агентных Claude-рутин.
> Детерминированные воркеры на Railway (скрапинг, диффы, перевод по глоссарию, импорт)
> разрешены и «идеального формата процесса» не ждут.

## Решение

Идея автоматизации правильная, но ставить рутину «как получится» — рано.
Принцип: **рутина ставится один раз и работает как часы** — значит, сначала
проектируем идеальный формат процесса, потом автоматизируем.

Почему рано (состояние на 30.07.2026):

- Конвейер обработки данных (importer, фазы 1–2: UZ-канонизация + перевод) —
  готов и в main. Но **автономного «нахождения данных» нет**: фаза 3
  (оркестратор — агентный поиск официальных источников) и фаза 4 (аудитор)
  не построены. Сейчас данные находим руками в сессиях.
- Человеческий гейт перед публикацией — осознанное дизайн-решение.
  Рутина, которая сама публикует юридический контент, его нарушила бы.
- Не определено разделение ролей между InspectorX и LegalX (см. ниже).

## Разделение по проектам (идея, зафиксировано со слов фаундера)

Мониторинг и ресёрч — это две разные задачи для двух разных проектов:

| Проект | Задача | Как автоматизировать |
|---|---|---|
| **LegalX** | Мониторинг уже известных источников (lex.uz и др. — все данные хранятся там) | Возможно, вообще без Claude-рутин — обычными Python-скриптами / cron / программной логикой внутри LegalX |
| **InspectorX** | Ресёрч: мы ещё не знаем, где лежат все нужные данные. Сначала найти требования, потом соединить их с LegalX | Ресёрч-рутина Claude (агентный поиск) — но только после того, как определён формат связки InspectorX ↔ LegalX |

Открытый вопрос перед запуском любой рутины: **какой «идеальный формат» связки
требований InspectorX с данными LegalX?** Пока формат не определён —
автоматизировать нечего.

## Заготовка: cloud-рутина «Мониторинг lex.uz» (спроектирована, не создана)

Полностью продуманная конфигурация — можно поднять за 10 минут, когда решим.
Read-only, ключи от БД не нужны, гейт публикации не нарушает.

- **Название:** «Мониторинг lex.uz — еженедельный отчёт»
- **Расписание:** каждый понедельник 09:00 по Ташкенту = cron `0 4 * * 1`
  (cron всегда в UTC; Ташкент = UTC+5)
- **Модель:** `claude-sonnet-5` (задача механическая, старшая модель не нужна)
- **Окружение:** Default (`env_01R5iYn8kdT9aM4b1KWRDsPT`, anthropic_cloud —
  создано автоматически 29.07.2026)
- **Репозиторий:** `TAVI-Agency/inspectorx-v2`

Что делает агент (черновик промпта, по шагам):

1. Собирает из репозитория все ссылки на lex.uz, на которые опираются
   требования (`grep` по `supabase/`, `docs/`, `src/`; уникальные URL,
   при большом количестве — приоритет самым частым).
2. **Грабли: на lex.uz `/docs/-N` и `/docs/N` — РАЗНЫЕ документы.**
   URL брать в точности как в репозитории, не «нормализовать».
3. Открывает каждую страницу и проверяет признаки изменений: дату последней
   редакции, пометки о поправках, статус «утратил силу» / «новая редакция».
   Если страница не открылась — пометка «не удалось проверить», это не считается
   изменением.
4. Ведёт файл-журнал `monitoring/lexuz-watch.md` (таблица: URL — название —
   дата редакции — статус — дата проверки). Первый прогон = фиксация baseline.
5. Каждую неделю открывает Pull Request с отчётом: что изменилось, что утратило
   силу, что без изменений. Если изменений нет — PR всё равно приходит
   с пометкой «изменений не обнаружено» (пульс, что мониторинг жив).
6. **В базу данных не пишет ничего, контент требований не меняет** — только
   отчёт. Решения о правках — за человеком (фаундер / юрист).

## Ограничения и грабли рутин (выяснено 29–30.07.2026)

- **Cloud-рутина получает чистый checkout репо с GitHub — без секретов.**
  `.env` / `.env.importer` в `.gitignore` (и это правильно), значит облачный
  агент не может писать в базу. Для read-only мониторинга это плюс,
  для полного конвейера — блокер (нужна отдельная настройка секретов).
- **Нужен Claude GitHub App на репозитории**, иначе облако не склонирует его:
  https://claude.ai/code/onboarding?magic=github-app-setup (делает фаундер,
  один раз). На 30.07.2026 не установлен.
- **MCP-коннекторы** к claude.ai не подключены (Supabase MCP в облаке не будет).
- **Local-рутина** видит локальные секреты и venv, но работает только когда
  Мак включён и приложение Claude Code запущено.
- Минимальный интервал cron-рутин — 1 час; `*/30 * * * *` отклоняется.
- Удаление рутин — только вручную через https://claude.ai/code/routines
  (агент удалять не может).
