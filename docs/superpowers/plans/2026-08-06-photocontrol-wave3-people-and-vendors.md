# Волна 3 — люди, вендоры, запуск (фотоконтроль упаковки)

> **For agentic workers:** это операционный runbook, а не кодовый план. Исполняется агентом ВМЕСТЕ с владельцем в отдельной сессии: используй superpowers:executing-plans для ведения чекбоксов. Задачи, где исполнитель — владелец / юрист / эксперт, агент не делает сам: он готовит вход, ведёт исполнителя по шагам (инструкции ниже — пошаговые, с URL и названиями кнопок) и проверяет выход. Вопросы владельцу — только бинарные, с рекомендацией. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** закрыть всё, что не сжимается скоростью разработки, — доступы и лимиты трат (гейт деплоя Волны 1 и включения Волны 2), часы юриста и эксперта (гейт первой продажи), внешних вендоров (Azure, LegalX), юридические тексты и выход на закрытую бету с первыми тремя платными клиентами.

**Контекст волн.** Волна 1 строит всё детерминированное ядро фотоконтроля + self-host OCR (код, миграции, воркер). Волна 2 включает LLM-контуры по приходу ключей (3–7 дней). Волна 3 (этот план) идёт параллельно обеим и содержит только людей, вендоров и запуск. Нормативный источник по существу продукта — `docs/PHOTOCONTROL_INTEGRATION_PLAN.md` (редакция 2, все 14 развилок §11 решены по рекомендациям).

**Роли:** владелец (фаундер, не технарь — все консольные шаги расписаны), юрист (верифицированный по контуру ADR-0001), эксперт (отраслевой, размечает фото-эталоны), агент (эта сессия: черновики, скрипты, проверки; **запись в прод-БД руками агента запрещена** — SQL по проду исполняет владелец в SQL Editor).

## Global Constraints

- Токены и ключи — только в `.env`-файлах из `.gitignore` (`.env.importer` и локальные `.env`); в git не коммитятся никогда.
- Запись в прод-БД делает владелец через SQL Editor панели Supabase; агент готовит SQL дословно и проверяет результат чтением (service-ключ `IX_SUPABASE_SERVICE_KEY` жив — `docs/INFRA_ACCOUNTS.md`).
- Мёрж в `main` автоматически накатывает миграции Supabase на прод без отката — поэтому `pg_cron` включается в Dashboard **до** мёржа миграций Волны 1 (задача А6), а миграции попадают в `main` только готовыми.
- Первый живой LLM-прогон (включение Волны 2) — **только после** выставленных лимитов трат у всех провайдеров (задача А5). Это гейт, а не пожелание.
- Продажа фотоконтроля возможна только после: подписанных юристом табачных фикстур (Б2), экрана согласия (Г1), вычитанных текстов отчёта (Г2), утверждённой цены и квоты (Д2).
- Устаревание вердиктов при изменении нормы до этапа-6-функциональности покрывает только ~30 табачных требований — **эту функцию до тех пор не продаём и не обещаем** (план §2 шаг 7, риск 13).
- Бета продаётся под **макетный** сценарий (PDF до печати), не под фотографии (решение развилки 13); квота беты — 5 проверок / 30 дней (развилка 12).
- Деструктивные действия (rm, drop, отзыв токенов, force-push) — только после подтверждения владельца.
- Текст — русский; код, имена переменных, коммиты — английский.
