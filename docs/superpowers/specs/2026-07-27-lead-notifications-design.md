# Уведомления о заявках в Telegram — дизайн

> Утверждено 27.07.2026. Закрывает пункт блока A чек-листа запуска
> («таблица заявок + уведомление нам в Telegram» — таблицы были, уведомления не было:
> заявка падала в базу молча).

## Решения (приняты фаундером 27.07)

1. **Канал — Telegram-бот.** Мгновенно, приходит на телефон, не тонет в спаме.
   E-mail отвергнут: нужен внешний отправитель с ключом, письма проваливаются в спам.
2. **Ловим все три таблицы заявок:** `subscription_requests` (деньги),
   `content_requests` (спрос на контент), `user_questions` (требуют ответа в срок).
   Механизм один, каждая таблица — один триггер.
3. **Контакты кладём прямо в сообщение** — чтобы звонить сразу, не открывая панель.
   Осознанная цена: ПД клиента уходят на серверы Telegram. Тот же класс риска, что
   Supabase вне УЗ, уже зафиксированный в чек-листе (блок D).
4. **Механизм — триггер в БД + `pg_net`** (не edge-функция). Мотив: деплой edge-функций
   требует `supabase login` под аккаунтом-владельцем, который сейчас недоступен
   (CLI видит чужой аккаунт); плюс это была бы первая edge-функция в v2 — новый
   рантайм ради одного HTTP-запроса.

## Архитектура

```
INSERT в subscription_requests / content_requests / user_questions
  → триггер notify_new_request()        (формирует текст под таблицу)
    → notify_admin_telegram(text)       (читает секреты, шлёт запрос)
      → pg_net → api.telegram.org/bot<token>/sendMessage
```

Две функции, три триггера, одна миграция. Стиль повторяет существующие функции схемы
(`handle_new_user`, `is_subscriber`): plpgsql, `security definer`, фиксированный
`search_path`, комментарии по-русски.

## Секреты

Токен бота и chat_id живут в **Supabase Vault** под именами `telegram_bot_token` и
`telegram_chat_id`; заводит их владелец проекта в панели. В репозиторий не попадают,
в коде не упоминаются — функция читает `vault.decrypted_secrets` в момент отправки.
Секретов нет (локальная база, дев) → уведомление молча пропускается.

## Формат сообщения

Обычный текст, **без Markdown/HTML-разметки**: имя клиента с любыми символами не
сломает сообщение и не даст подставить в него разметку.

```
🔔 Заявка на подписку
Имя: Иван Иванов
Контакт: +998 90 123-45-67
Компания: TAVI
27.07.2026 14:30
```

Для `content_requests` — вид заявки, текст запроса, комментарий; для `user_questions` —
первые 300 знаков вопроса и пометка «СРОЧНЫЙ», если стоит флаг. Время — по Ташкенту.

## Инвариант устойчивости (главное)

**Отказ уведомления не может отменить заявку.** Обе функции завёрнуты в
`exception when others → raise warning`: нет расширения, нет секретов, Telegram лежит,
токен отозван, сеть недоступна — строка всё равно вставляется, ошибка уходит в лог
Postgres. Лид дороже уведомления. Проверяется отдельным негативным прогоном
(заведомо неверный токен → вставка проходит).

## Доступ к функциям

`notify_admin_telegram` — `security definer` и умеет слать сообщения нашим ботом,
поэтому право выполнения **отзывается** у `public`, `anon`, `authenticated`: иначе любой
анонимный посетитель мог бы вызвать её через PostgREST и завалить нас сообщениями.
Вызывается только триггерами (от владельца) и service-ролью.

## Проверка

SQL-тестов в проекте нет, поэтому проверка живая, тремя шагами:

1. Вставка тестовой заявки service-ключом → сообщение пришло (подтверждает человек).
2. Негативный прогон: временно неверный токен → вставка проходит, сообщения нет.
3. Тестовые строки удаляются; заодно чистятся старые тестовые данные из блока C
   чек-листа (3 юзера `ix.regtest*.20260712`, 2 заявки, 1 content_request).

## Известные ограничения

- **Ретраев нет.** `pg_net` отправляет асинхронно и не повторяет попытку: если Telegram
  недоступен в эту секунду, уведомление потеряно (заявка — нет). Приемлемо при потоке
  в единицы заявок; при росте — переезд на edge-функцию с очередью.
- **Схема `pg_net` различается между проектами** (то `net`, то `extensions`), поэтому
  `search_path` функции включает обе.
- Ответы Telegram оседают в `net._http_response` — там смотреть, если сообщения
  перестанут приходить.

## Что делает владелец проекта руками

Мои доступы этого не позволяют: создать бота у @BotFather, узнать chat_id, включить
`pg_net`, выполнить миграцию в SQL-редакторе, завести два секрета в Vault.
Точные шаги — в комментарии к миграции.
