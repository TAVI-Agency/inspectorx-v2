# Журнал отложенных изменений — слой «Проверка юристом» (29.07.2026)

Сюда записано всё, что в ходе сессии показалось нужным удалить, переименовать
или поменять несовместимо. По правилам сессии ничего из этого НЕ сделано —
только новый код и аддитивная миграция. Применять решает владелец.

## 1. Каскад стирает историю уведомлений юриста

**Что:** `lawyer_notifications.review_id` ссылается на `requirement_reviews`
с `on delete cascade`. Удаление заключения удаляет и уведомление
`review_published`/`review_rejected` — юрист теряет след «у вас было
заключение, его удалили».

**Зачем менять:** если захочется сохранять историю уведомлений — заменить
каскад на `on delete set null` (текст уведомления и так строится по `kind`).

**Каким SQL:**
```sql
alter table public.lawyer_notifications
  drop constraint lawyer_notifications_review_id_fkey,
  add constraint lawyer_notifications_review_id_fkey
    foreign key (review_id) references public.requirement_reviews(id)
    on delete set null;
```

**Риски:** осиротевшие уведомления со ссылкой в никуда — UI уже переживает
`review_id = null`, но клик перестанет вести на заключение. Несрочно.

## 2. Порт Kong 54331 конфликтует с эфемерными портами macOS

**Что:** `supabase/config.toml` держит API на 54331 — внутри диапазона
эфемерных портов macOS (49152–65535). В этой сессии порт занял «осиротевший»
сокет в FIN_WAIT_2, и `supabase start` не поднимался. Локально на время
сессии порт менялся на 54341 и отключался analytics-контейнер (Logflare не
стартовал) — файл в коммит НЕ пошёл, изменение осталось в рабочей копии.

**Зачем менять:** убрать класс сбоев «занят порт» у всех локальных стеков.

**Какой правкой:** в `[api]` `port = 48331` (или любой ниже 49152; все
сервисные порты проекта 5433x — та же зона риска), `[analytics] enabled =
false` (локально не используется). После смены порта поменять URL в
`.env.local`-подобных настройках у всех, кто гоняет фронт на локальной базе.

**Риски:** разъедутся привычки/скрипты, которые помнят 54331. Несрочно —
до следующего конфликта.

## 3. Мусорные строки переноса v1 висят в очереди «Ждут проверки»

**Что:** очередь юриста фильтрует заглушки (`none`, `-`, `—`, пустые) кодом,
как это делает и список требований. Сами строки-заглушки остаются в базе
и продолжают числиться published.

**Зачем менять:** снять фильтры-костыли на фронте, не показывать мусор ни в
одном новом экране автоматически.

**Каким SQL:** снять с заглушек `status='published'` (перевести в
`archived`) — это UPDATE прод-данных, потому отложено:
```sql
update public.requirements r set status='archived'
from public.requirement_contents c
where c.requirement_id = r.id and c.lang = 'ru'
  and (btrim(c.title) = '' or lower(btrim(c.title)) in ('none','null','-','—'));
```

**Риски:** задеть строку с осмысленным, но коротким заголовком — перед
прогоном просмотреть выборку select-ом. Плюс пересчитаются счётчики витрины.
