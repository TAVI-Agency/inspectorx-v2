## Как включить утром (пошагово)

### 1. Ключи для Build-конвейера — `.env.importer`

Файл `.env.importer` в корне репозитория (gitignored, у вас уже есть — просто добавить
строки). Пример полного набора — `.env.importer.example`.

- **Обязательно** (без этого ничего живого не заработает):
  ```
  ANTHROPIC_API_KEY="sk-ant-..."
  ```
- **По желанию** — другие провайдеры моделей (Gemini, OpenRouter, Zro и т. п.), если
  захотите сравнить их по цене/качеству:
  ```
  LLM_PROVIDER_GEMINI_URL="https://generativelanguage.googleapis.com/v1beta/openai"
  LLM_PROVIDER_GEMINI_KEY="AIza..."
  LLM_PROVIDER_OPENROUTER_URL="https://openrouter.ai/api/v1"
  LLM_PROVIDER_OPENROUTER_KEY="sk-or-..."
  LLM_PROVIDER_ZRO_URL="https://zro.moonmath.ai/v1"
  LLM_PROVIDER_ZRO_KEY="..."
  ```
  Имя после `LLM_PROVIDER_` (например `GEMINI`) должно совпадать с тем, что прописано в
  `importer/build/models.yaml: providers` (какая модель у какого провайдера) — без строки
  там модель по умолчанию идёт в Anthropic. Сейчас `providers: {}` — пусто, заполнить
  вручную, когда решите, какие модели подключаете (или временно через
  `IMPORTER_TIER_CHEAP` / `IMPORTER_TIER_MID` / `IMPORTER_TIER_EXPENSIVE` — подменить модель
  тира без правки файла, удобно для разовых сравнений).
- **Веб-поиск** (нужен для Cartographer `--research`):
  ```
  WEBSEARCH_BACKEND="serper"   # или "tavily", или "live" (встроенный поиск Claude, без своего ключа)
  SERPER_API_KEY="..."         # для serper.dev
  TAVILY_API_KEY="tvly-..."    # для tavily
  WEBSEARCH_ALLOWED_DOMAINS="lex.uz,gov.uz,customs.uz,standart.uz,eec.eaeunion.org,norma.uz"
  ```
  Allowlist доменов — рекомендуемый набор для Узбекистана; без него поиск может принести
  ссылку на любой сайт (защита от совсем левых хостов есть в коде отдельно, но allowlist —
  это второй, более узкий рубеж, и его лучше не пропускать).
- **Страховка от разгона цикла** (не денежный лимит, просто потолок вызовов на процесс):
  ```
  IMPORTER_LLM_MAX_CALLS="400"
  ```
- **Важное напоминание**: прежде чем в первый раз запускать что-либо с реальным ключом —
  выставьте лимиты трат в консоли каждого подключаемого провайдера (Anthropic, и любых
  дополнительных из списка выше). Это тот же пункт А5, что был записан для Волны 3
  фотоконтроля, — правило одно и то же для всех LLM-провайдеров в проекте.

### 2. Сравнение моделей — `python -m importer build eval-models`

```bash
python -m importer build eval-models \
  --set cheap=claude-haiku-4-5,mid=claude-sonnet-5,expensive=claude-opus-5 \
  --set cheap=gemini-3.1-flash-lite,mid=deepseek-v4.1-flash,expensive=claude-sonnet-5
```

Команда прогоняет golden-набор на каждом наборе моделей (`--set` можно повторять) и печатает
таблицу-сравнение по строке на набор. Колонки — метрики качества (доля правильно найденных
требований, доля верных решений Verifier'а на правильных и на «обманках», точность
категории) и `errors` — сумма сбоев прогона. Больше в столбцах качества — лучше; больше в
`errors` — хуже (нестабильность или дыры в проводке ключей). Каждый прогон также сохраняет
подробный JSON в `importer/golden/eval-reports/`.

**Важно**: три модели внутри одного `--set` (cheap/mid/expensive) обязаны быть разными
моделями — если случайно указать одну и ту же модель на два тира, команда откажет с ошибкой
(это защита, чтобы модель-проверяющий не проверяла сама себя, сделано в этой ночной волне).

### 3. Живой прогон карты с поиском — `build map --research`

```bash
python -m importer build map --group <ref> --jurisdiction UZ --research
```

Без `--research` карта строится только по знаниям модели из памяти. С флагом — Cartographer
сначала составляет план поисковых запросов, реально ищет (через выбранный `WEBSEARCH_BACKEND`)
и скачивает найденные документы. В конце команда печатает:

- `sources_used=<число>` — сколько источников реально попало в карту;
- список пропущенных запросов/ссылок с причиной (например, документ не разобрался или
  адрес не прошёл проверку безопасности) — это не ошибка всего прогона, просто предупреждение,
  на что стоит посмотреть глазами.

Карта после этого всё равно требует вашего апрува (`build approve-map`) — `--research`
только подкладывает реальные источники, решение остаётся за вами.

### 4. Vercel — Sentry и аналитика

Project Settings → Environment Variables, добавить одну или несколько:

- `VITE_SENTRY_DSN` — включает отправку ошибок в Sentry (сейчас в проде их не видно вообще).
- `VITE_PLAUSIBLE_DOMAIN` **или** `VITE_YM_ID` (Яндекс.Метрика) — счётчик посещений.

После добавления — **Redeploy** (просто сохранить переменную недостаточно, нужен новый
деплой, чтобы она попала в собранный бандл).

**Предупреждение**: Метрику (или Plausible) включать только после того, как на сайте
опубликована политика конфиденциальности с упоминанием счётчиков/cookie — иначе это риск с
законом о персональных данных. Сейчас `/legal/privacy` есть, но текст не опубликован
(`published: false`), так что пока аналитику включать не стоит — сначала блок «юр-страницы»
ниже.
